## M1 baseline for an implementation request

The proposed M1 baseline selects P01, P03, P04, P07, P10, P11, and P15 as refined by the concrete contracts above: core-v1 DAG, explicit models, five node types, one provider call per provider by default, three across all workspaces through application settings, one native Context writer, serialized shared working directories, supervised Node/loopback transport, immutable stored inputs/outputs, and no automatic retries.

Native configuration starts in the prototype-compatible **Restricted** profile. **Inherit** is a visible opt-in setting supported only by adapters that can enforce the subscription/billing policy. Full Access remains the selected tool-access policy; changing the native configuration profile is recorded with the invocation.

D01–D18 remain confirmed requirements. Proposed details are not marked human-approved by this documentation update. A later explicit request to implement M1 using this baseline can supply implementation authorization and acceptance together; no separate ritual approval of seven proposal IDs is necessary.

## Out of scope

Automatic Git/worktree management, commits as task identity, arbitrary Script nodes, unrestricted feedback edges, remote workers, native-session rewind, and automatic deployment remain outside these milestones. Reference-pipeline completion produces an inspectable accepted candidate, not an automatic production release.
