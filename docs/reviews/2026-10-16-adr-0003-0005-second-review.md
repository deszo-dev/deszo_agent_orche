## Remaining findings

### ADR3-S01 (high): touched paths are only known after implementation, so the floors must also be checked against the candidate

The floor table keys on "Touched paths match declared critical areas" and "Changed public interfaces, schemas". §1 says the runtime derives these "from the captured source snapshot … before plan selection". Before implementation, however, the snapshot is the *unchanged* source. Which paths will be touched is precisely the Analyst's anticipated scope, which is the subjective judgement the floor is supposed to override.

In the failure case the floors exist for, the Analyst declares a local UI change and the Developer then edits a migration or a schema. No planning-time floor fires, because nothing in the unchanged source reveals that.

Recommendation: evaluate the floors at two points.

1. **At planning time**, over the anticipated scope plus static facts the runtime can compute from the unchanged source, such as fan-out of the named components and consumers of named interfaces.
2. **At candidate time, as a mandatory check.** Before delivery review, the runtime compares the assembled candidate's actual changed paths, schemas and interfaces against the plan's floors. If the candidate exceeds them, the runtime must create a plan revision that adds the missing stages and checks before review or acceptance can proceed. The current candidate's checks and approvals stay valid only where the revision keeps them applicable.

Add a fixture that matches the Stage 3 case "deliberately underestimated critical change". The floors must fire on the candidate even though the assessment and the planning-time facts were low.

### ADR3-S02 (medium): the critical-area list must be project policy, not Deszo's paths

The floor table hard-codes Deszo's own files: `docs/storage/m*.sql`, `launch_shim.rs`, `supervisor.rs` and `docs/schemas/*.json`. ADR-0003 specifies a *general* development workflow for arbitrary target projects. Make the critical-area and public-interface declarations versioned per-project policy data, captured with the plan inputs. Use Deszo's list as an example of such a declaration.

A project without a declaration should fall back to a conservative default, for example the full reference stages. The absence of a declaration must never mean the absence of floors.

### ADR3-S03 (low): the per-run invocation estimate looks low

The estimate assumes 6–10 managed invocations per run. The reference workflow alone has at least eight invoked steps:

- Define;
- two readiness reviews;
- Test Author;
- Developer;
- two delivery reviews;
- acceptance.

On top of that come the assessment run, Map tasks and repair cycles. State the basis per case class, or widen the range, for example 10–40 per run, so the authorization decision rests on a realistic upper bound.

### ADR4-S01 (low): define what fingerprint version 1 is

`fingerprint_version: 2` implies an existing version 1, but today's Gate and Map fingerprints carry no explicit version field. Their composition was also refined during the M1–M6 review fixes (the reviewer fingerprint closure and native profile). In the contract, define version 1 as the current composition and record it explicitly on new records from the version-2 migration onward, so legacy records are interpreted unambiguously.

### ADR5-S01 (low): two separate-clone details

- **`--shared` alternates.** A `--shared` clone borrows the caller's object store. A `git gc` or prune in the caller's repository during a long delivery can remove objects the clone still needs. Prefer a local clone with hardlinks, or `--reference` with `--dissociate`, or state that delivery holds the reference only for its own short duration and verifies the objects before commit.
- **Hooks.** A fresh clone has no hooks; the caller's `.git/hooks` are not copied. If the commit policy requires the project's hooks, they must be installed explicitly in the clone from a declared source, for example via `core.hooksPath` to a captured hook set, and recorded. Otherwise the policy records that no hooks ran. The current text ("Hooks run inside the isolated clone") implies they exist there automatically.
