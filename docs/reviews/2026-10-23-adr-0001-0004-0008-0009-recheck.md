## Additional findings

### AMD-16 (low): ADR-0008 §9.3 describes seven receipt states in SQLite; the implementation splits them differently

§9.3 says the lifecycle states `requested`, `quiescing`, `stopped`, `activated`, `started`, `confirmed` and `failed` are "durably recorded in SQLite and the Host event journal". The two stores actually hold different things:

- **SQLite** (`lifecycle_operations` in m14) holds only `intent` and `verified`.
- **The Host journal** (`operations.ndjson` in `lifecycle-host`) holds the phases, under different names: `activation_accepted`, `shutdown_requested`, `old_process_stopped`, `managed_process_tree_stopped`, `candidate_activated` and `activation_failed`.

Fold this into the §7 and §9 update in AMD-08. Say which store holds which phase, and map the ADR's state names to the journal's names. ADR8-07, recovery after a crash in each restart phase, depends on that mapping.

### AMD-17 (low): the digest format in the §5.2 example does not match the schema

The proposal example in §5.2 uses `"candidate_digest": "sha256-a1b2c3d4..."`. m14 requires `length(candidate_digest) = 64`, which is a bare hex SHA-256, and the implementation passes the bare value. Use the stored format in the example, or state that the prefix is removed before storage.
