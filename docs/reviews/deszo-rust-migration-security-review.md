# Deszo Rust migration independent security review

**Reviewed on 2026-11-06**

Scope covers proposed ADR-0012 and the working-tree design for separating the repairable Engine from trusted Host authority.

## 1. Executive verdict

The proposed design permits an unauthorized Repair to reach installation even if every planned sandbox control works. A malicious Engine can present invented Parent, incident and Repair identifiers, claim a slot, and submit an otherwise eligible patch. The Host then runs its own Gate and acceptance Judge, but neither establishes that the Parent Judge authorized this Repair. The acceptance record in this scenario can be genuine while the update is unauthorized under the existing contract. Design 04 §2.2 explicitly permits this path. [Design 04 §§1–2](../system-design/rust-migration/04-self-repair.md#L26), [ADR-0010 §§1, 4–5](../adr/0010-p6-trusted-build-activation-rollback.md#L11), [Current protected Gate](../../runtime/core/p5Gate.mjs#L754)

Host-owned Admission and an Engine channel with no installation verbs are sound structural choices. The smallest correction to the authorization gap is a Host-owned, single-use Parent authorization checked before slot allocation, independently of later P5 acceptance. The design also needs a Host-owned source of Workflow resource grants, a clear trust decision for compromised Judge execution, and a closed acceptance-to-selector contract. Direct access to Host authority and cross-Workflow escape remain unproven for the proposed Windows launch and grant model. [Design 03 §§1, 4–7](../system-design/rust-migration/03-trust-boundaries.md#L3), [Design 05 §§3, 5–7](../system-design/rust-migration/05-store-and-api.md#L36)

## 3. Threat model

Assume arbitrary execution as an accepted or compromised Engine, a candidate test/build process, a provider CLI, or any of their descendants. Candidate-controlled inputs include Git objects, paths, test and build output, provider text, and all ordinary Store records. The protected assets are the Host, Shell and launch configuration, Owner Token, protected policy and grants, authorization and acceptance evidence, installed packages and selector. Authorization also covers isolation between Workflow resource sets. Assume an uncompromised OS and trusted installer, Host and Shell. An uncontained process already under the Owner's account is in the Owner trust domain. An in-scope process causing such a launch or using it as a deputy is an escape. [Design 02 §§1–3, 7](../system-design/rust-migration/02-target-architecture.md#L7), [Design 03 §§5–7](../system-design/rust-migration/03-trust-boundaries.md#L86)

## 5. Host authority and IPC

The complete proposed Engine message catalog omits stage, switch, selector mutation, fence, attach, legacy activation, acceptance writes, receipt creation and enrollment/policy change. Host Custody scopes records by lineage and excludes Host-owned jobs. Internalizing stage/switch removes the direct route when all child-reachable legacy listeners and alternate entry points are removed. The current Rust Host dispatches lifecycle, stage, switch and Custody commands behind one bearer check, so the target requires a change in dispatch and launch topology. [Design 03 §4](../system-design/rust-migration/03-trust-boundaries.md#L74), [Design 05 §5](../system-design/rust-migration/05-store-and-api.md#L104), [Current Host](../../lifecycle-host/src/lib.rs#L1786), [Custody commands](../../lifecycle-host/src/custody.rs#L681)

The Host should bind authority to its endpoint, process instance, role, generation and allowed phase. Treat child-supplied IDs as lookup data. Use separate responder/request namespaces, direction checks, bounded decoding and operation-specific replay checks. Cover every listener, inherited handle, duplicate/open-process path, Shell bridge and broker. Refuse unknown verbs, cross-lineage or cross-role custody, maintenance requests beyond preflight, and attempts to use an approved launch to reach an external deputy. An Engine `DrainAck` cannot prove process termination, and `MaintenanceReady` cannot authorize a switch. `ClaimSlot`, `SubmitCandidate` and `Custody::Launch` are indirect authority paths when their preconditions originate in the Engine. Findings SR-01, SR-02 and SR-05 address those preconditions. [Design 02 §§1, 8](../system-design/rust-migration/02-target-architecture.md#L7), [Design 04 §§2, 7](../system-design/rust-migration/04-self-repair.md#L38), [Design 05 §§5–6](../system-design/rust-migration/05-store-and-api.md#L104)

## 7. P2 authorization and P5 acceptance

P2 establishes permission to open the specific Repair for the Parent incident. P5 establishes whether a particular candidate from that Repair may be installed. The current workflow Judge applies `request_repair` in the Engine. The linked Repair logic checks the designated Parent Judge and captured publication, profile, incident and failed attempt, then persists `ParentRepairAuthorization`, the continuation checkpoint and link in the Engine Store. The Gate binds to that exact authorization. Later Repair Judge approval and the handoff tie the exact verified candidate to P2 and P5 evidence. That establishes the product contract in current code. The current Store writer cannot supply a trustworthy copy for the new Host. [ADR-0009 §6](../adr/0009-workflow-native-judge-and-exclusive-external-input.md#L155), [Parent decision](../../runtime/core/workflowJudge.mjs#L825), [Authorization checks](../../runtime/core/linkedRepair.mjs#L966), [Authorization write](../../runtime/core/linkedRepair.mjs#L1052), [Gate binding](../../runtime/core/p5Gate.mjs#L754), [Handoff](../../runtime/core/linkedRepair.mjs#L478)

Move the protected authorization decision and evidence, with its inputs, to the existing trusted Host boundary. The Host needs a verifiable Parent Run start under a pinned publication, a valid incident tied to the exact subject and attempt, and a directly authenticated invocation and output of the enrolled Parent Judge. A Host digest of an Engine-authored incident or verdict cannot supply those facts. Use the narrow trusted event producers required for the authorization predicate, such as gateway-observed starts and Host custody observations, with the full scheduler, suspension and ordinary history remaining in the Engine. If a required incident condition depends on Engine-only facts, give it a trusted observer or explicitly revise the policy with the Owner. A Host receipt should bind installation, profile, root, active generation and baseline, both publications, Parent, failed attempt/incident, authorized Repair and permitted scope, with a nonce and durable consumption by one claim. Gate, acceptance and selector commit join back to that same receipt. [Design 04 §§1–2](../system-design/rust-migration/04-self-repair.md#L26), [ADR-0012 §§5.3–5.4](../adr/0012-rust-first-backend-and-engine-lifecycle.md#L55), [Root-bound Parent amendment](2026-11-04-p6-genuine-contract-amendment.md#L15)

## 8. Judge provenance and Owner answers

Admission should retain the proposed Host-constructed, immutable dossier and invocation. Bind the role, enrolled profile, tool and load/configuration identity, provider session, nonce, Parent/Repair subject, snapshot, verification and dossier digests to a dedicated contained invocation. Seal the Host capture and complete result before recording a verdict. Preserve channel separation from Developer, Gate and ordinary Judge processes, including their descendants and writable configs. Label narratives and captured candidate text as untrusted. Bound what a follow-up `request_evidence` can retrieve. On restart, abandon partial captures and reissue with a fresh identity, or resume only against a complete matching durable record. [Design 04 §§4, 9](../system-design/rust-migration/04-self-repair.md#L95), [Current Custody tool binding and spool](../../lifecycle-host/src/custody.rs#L1157)

Host capture proves which enrolled local invocation emitted bytes. A compromised enrolled CLI can emit a schema-valid `accept_repair` on its own pipe. If the Owner delegates judgment to that executable, its false verdict is an explicit trust limitation within deterministic gates and containment. If the requirement is to withstand its compromise, require an independently authenticated decision bound to the exact dossier and nonce, or another independent policy-authorized decision maker. A model's incorrect or manipulated judgment can still pass a sound provenance check. [Design 03 §§5, 7](../system-design/rust-migration/03-trust-boundaries.md#L86), [Design 04 §§4.2–4.4](../system-design/rust-migration/04-self-repair.md#L107)

The trusted Shell must render the protected question and subject from a Host-owned view. An authenticated answer to an Engine-presented question ID alone leaves room for relabeling a genuine pending question. Bind answer and authenticated caller to the displayed question digest, operation, invocation, dossier and exact subject, and consume it once while pending. Keep the existing answer route with Host-owned dispatch for protected questions. Only the enrolled Judge can initiate a protected question. Ordinary Judge questions remain workflow-domain records. [Design 04 §4.3](../system-design/rust-migration/04-self-repair.md#L115), [Design 05 §6](../system-design/rust-migration/05-store-and-api.md#L130), [Current answer checks](../../runtime/core/workflowJudge.mjs#L1121), [ADR-0009 §§3–5](../adr/0009-workflow-native-judge-and-exclusive-external-input.md#L69)

## 9. Windows containment

The recorded Windows 11 Home, non-admin spike demonstrated an AppContainer child's denial of parent open/memory access and ungranted folder reads/writes, with granted folder access working. Loopback timed out in that setup. Explicit handle lists isolated two contained test children. The ordinary child had valid foreign handle values, but consumed payloads confounded the data-read test. A default named-pipe DACL admitted a same-user child. The attempted explicit AppContainer DACL did not admit its intended client, for an unresolved reason. The CommonJS loader observations do not establish Node ESM or production Rust containment. Descendant tokens, cross-container access, handle duplication and packaged policy remain unproven. [Decision C §§5.1–5.5](2026-11-06-p6-decision-c-design.md#L109)

Use OS identity and ACLs for actual files, objects and process rights. Set the AppContainer or LPAC token, network restrictions, explicit handle list and no-breakaway Job before untrusted instructions execute. Check all launch and security calls and terminate on setup failure. Keep Job and server pipe handles private. Validate read, write, duplication and process-creation rights against Host, Shell and other roles. Test fresh child and grandchild tokens, process broker routes, and concurrent spawns with fresh channel payloads. A Job controls lifetime. Each token and grant set must independently constrain file, process and network access. The current Custody launcher has a suspended-start, explicit-stdio and Job assignment pattern. The old Host path also has a spawn followed by Job assignment. Neither establishes the new AppContainer policy. ## 10. Workflow-scoped Full Access

OD-1 permits full operational access to explicitly authorized Workflow resources. Per-identity ACLs can express several distinct filesystem roots with read/write/execute modes. A long-lived Engine with direct ACL grants sees their union, and a Run ID in an Engine message cannot narrow its token. A reusable provider SID with simultaneously applied grants has the same problem. Host launch policy also cannot safely depend on Workflow publications and grants that the Engine can rewrite. As proposed, the Engine can widen its effective access directly through the union or indirectly by asking Custody to launch into a different scope. [Design 02 §7](../system-design/rust-migration/02-target-architecture.md#L121), [Design 03 §3](../system-design/rust-migration/03-trust-boundaries.md#L61), [Design 05 §§4, 6–7](../system-design/rust-migration/05-store-and-api.md#L87), [Design 09 PR-2 and §3](../system-design/rust-migration/09-open-decisions.md#L9), [Current Custody reservation and launch](../../lifecycle-host/src/custody.rs#L835)

Keep an Owner-authenticated immutable resource manifest in Host state for each published policy and bind a Host-issued Run/attempt ticket to it. Include physical roots, modes, approved executables and helpers, network destinations or approved services, credential scopes, scratch/cache and budgets. Require a new authenticated version or explicit Run amendment for additions. Start an appropriately scoped process or broker operation under the amended policy. Keep direct cross-Workflow workspace grants off the global Engine. Use scoped workers or a narrow broker that validates the current Host ticket, operation and resource on every launch or privileged open. Data deliberately returned into the shared Engine remains visible to that Engine. If isolation also requires confidentiality of returned data between Runs, the data-handling work must remain in per-Run principals. Network capability flags alone do not encode an endpoint allowlist. Apply network policy or use an endpoint-restricting broker if the Workflow authorizes specific destinations. [Design 09 OD-1 and §3](../system-design/rust-migration/09-open-decisions.md#L17), [Microsoft AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation)

Validate root and target object identities under OS enforcement. Handle overlaps, junctions, symlinks, mount points, hard links, alternate path syntax and retargeting between validation and use. Reject any grant exposing Host-private state or allowing an untrusted principal to alter a privileged executable or its load path. Ensure descendants receive the same or narrower authority. A Host allowlist for the first executable does not enforce what descendants can execute. Scope each temporary build and provider cache, and keep credentials and mutable settings out of shared writable state. Test multiple concurrent Workflows with different roots and toolsets, both positive access and cross-Run denial. For Git publication, authorize the exact repository, remote and operation in a scoped job and supply only its approved credential. Disable an incompatible provider for the protected path. Earlier UI labels and provider flags do not establish equivalent permissions, so document any previously working resource that now requires explicit authorization. [Design 04 §§2–3, 5](../system-design/rust-migration/04-self-repair.md#L38), [Design 09 §§1–3](../system-design/rust-migration/09-open-decisions.md#L5), [Current providers](../../runtime/core/adapters.mjs#L177), [Current Full Access label](../../src/App.tsx#L803), [Microsoft reparse points and file operations](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points-and-file-operations)

## 11. Owner Token and API

The Host keeps the broad bearer, authenticates at loopback, and forwards caller classification and permitted inputs. The bundled Shell/WebView receives the token over a separate trusted path. Owner-run external clients retain broad API authority through descriptor discovery. For containment, exclude both current and old token/descriptor paths from every job, strip credentials from child environments and inherited handles, deny container access to the gateway, and keep the Shell/WebView bridge available only to its trusted UI context. The Host must originate the caller identity, exclude the bearer from forwarding and logging, correlate replies to pending requests, and keep Host-owned routes outside Engine control. Scope controller/Judge credentials to Engine-domain operations, with explicit Host checks on protected grants, questions and Stop. Preserve route auth, token refresh and external client discovery in contract tests. [Design 05 §§5–7](../system-design/rust-migration/05-store-and-api.md#L104), [Current caller classification](../../runtime/runner.mjs#L195), [Tauri connection](../../src-tauri/src/main.rs#L434), [UI transport](../../src/transport.ts#L8), [MCP discovery](../../mcp/runtime-client.mjs#L12)

The proposed cutover retains the old token value. Decision C establishes that the old topology made that value readable to Engine children on the test-owned installation. Relocating a previously readable bearer cannot revoke a copy. Treat Node-era bearer material as potentially exposed at a protected cutover. Rotate through the Host, retire old listeners and descriptors, and rebootstrap UI and external clients against the fresh descriptor. This changes one cutover credential value while preserving the authority of the Owner Token and the API contract. [Design 05 §§4, 7](../system-design/rust-migration/05-store-and-api.md#L96), [Design 06 §5](../system-design/rust-migration/06-migration-plan.md#L90), [Decision C §2](2026-11-06-p6-decision-c-design.md#L23)

## 12. Store integrity and recovery

The separation is appropriate if OS policy denies access to Host files and memory. The Engine can still rewrite ordinary publications, grants, eligibility displays and history. Their digests establish bytes, and Host IDs reflected in ordinary events are display references. Neither supplies provenance. Host-owned reads and events must drive every protected action. During cutover, historical Node records can identify slots conservatively as consumed after Host validation against the enrolled pool. Historical records cannot authorize any new Repair, acceptance or build. [Design 05 §§2–4](../system-design/rust-migration/05-store-and-api.md#L18), [Design 04 §§9–10](../system-design/rust-migration/04-self-repair.md#L239)

Specify one durable decision per protected transition. The current proposal lists an fsynced journal, slot file, successor file and selector without an atomicity or derivation rule joining them. Record request kind, principal/installation/profile, payload fingerprint and outcome in the authoritative transition. Commit a slot claim, authorization consumption and attempt/budget charge together. Persist referenced bytes before journaling decisions. Differentiate a durable operation from a fresh pipe/process instance, and an exact idempotent replay from an authorized new attempt on the same slot and candidate. Interrupted checks, Judge sessions and builds yield no reusable positive evidence. A new attempt needs fresh invocation identities and revalidation of the original scope and current invalidation state. [Design 04 §§2, 9](../system-design/rust-migration/04-self-repair.md#L38), [Design 05 §§3, 5](../system-design/rust-migration/05-store-and-api.md#L48)

Use the selector as the commit authority and derive any missing successor/index record from the exact prepared operation bound by the selector. Hold on torn or ambiguous evidence, unresolved termination, stale acceptance, inconsistent hashes or a fork. No ordinary Engine row may repair that state. Define recovery for claim, attempt, receipt, stage, invalidation, selector and successor boundaries, including profiles that share the installation selector. [ADR-0010 §§7–8](../adr/0010-p6-trusted-build-activation-rollback.md#L117), [Design 04 §§8–9](../system-design/rust-migration/04-self-repair.md#L208), [Existing reconciliation](../../lifecycle-host/src/engine_switch.rs#L1051), [Existing installation/profile paths](../../lifecycle-host/src/lib.rs#L615)

## 13. Cargo build and verification isolation

The lockfile, protected manifests/config and vendoring constrain the graph. Treat build scripts, procedural macros, toolchain/linker subprocesses, native libraries, generated files and candidate test binaries as arbitrary execution within Verify and Build. A script can have a nondefault filename or include allowed paths. Audit the complete executable input closure if policy intends to forbid changes to build scripts or workspace macros. Cargo can merge configuration from working-directory ancestors, and a sanitized `CARGO_HOME` alone does not pin wrappers or tool discovery. Use a sealed Host-created work root, pinned absolute executables and load paths, a fully identified linker/SDK and vendor set, allowlisted environment including home/temp, and fresh per-job scratch, target and writable caches. Materialized snapshots and tool inputs should be read-only. OS policy must deny Host and ordinary Store, private processes/handles, credentials, unrelated Workflows and network to both jobs and all descendants. Cargo offline mode constrains Cargo's own fetch behavior. [Design 04 §§3.2, 5–6](../system-design/rust-migration/04-self-repair.md#L79), [Cargo configuration](https://doc.rust-lang.org/cargo/reference/config.html#hierarchical-structure), [Cargo build scripts](https://doc.rust-lang.org/cargo/reference/build-scripts.html), [Rust procedural macros](https://doc.rust-lang.org/reference/procedural-macros.html), [Cargo offline flags](https://doc.rust-lang.org/cargo/commands/cargo-build.html)

Accept only bounded regular output files with the expected native identity and name after the job tree is proven terminated. Prevent junction, link and rename substitution during Host collection. Hash the bytes the Host actually copies into private staging and then launches. A deterministic hostile output can match twice. Reproducibility supplies repeatability evidence and neither semantic correctness nor process containment. For Gate, distinguish test selection, completion and expected assertion from a zero exit code emitted by a candidate-controlled process. Preserve an incident-bound, independently observed failure predicate and a positive baseline control. [Design 04 §§5–7](../system-design/rust-migration/04-self-repair.md#L125), [P5 causal contract](2026-10-30-p5-closure-architecture-amendment.md#L50)

## 14. P6 package and switch integrity

Bind the Host chain to one prepared operation. Its record should join installation/profile, root and effective enrollment, active selector generation and baseline identity, single-use Parent authorization, slot, candidate Git commit/tree/object format and strong snapshot digest, protected policy, verification, Judge decision and acceptance. Attach the pinned builder/launcher identity, toolchain and native inputs, vendor/lock, target, flags, both build job/output identities, exact manifest and package hashes, and target Shell/Store/protocol compatibility. Compare the exact immutable staged bytes at preflight and activation. Give the build a Host-assigned ID before compilation, then bind it to final bytes in the receipt. Deriving the embedded ID from a receipt that hashes the binary and manifest containing it is circular. [Design 02 §6](../system-design/rust-migration/02-target-architecture.md#L109), [Design 04 §§6–7](../system-design/rust-migration/04-self-repair.md#L145), [ADR-0010 §§5, 7](../adr/0010-p6-trusted-build-activation-rollback.md#L76)

Preserve G0 in order. Fence new custody launches and independently establish quiescence, terminate A and prove its tree ended, guard the real Store and sidecars and start B with access to a disposable copy only. Bind B's report to the exact preflight process, package, generation and copy. Trust the Host's structural compatibility observations and treat B's self-report as a report from candidate code. The shared `DeszoEngine` ACL proposed for normal operation does not establish copy-only preflight. Use an effectively distinct per-launch identity or proven equivalent, disable ordinary requests while in maintenance, and grant production access only after durable commit and guard release, before normal execution. Serialize protected invalidation/Stop with the final selector comparison and write. A Stop durably admitted first blocks commit, including a Stop before claim on the protected subject. Pre-commit fallback requires proven termination and an unchanged Store. After commit, reconcile forward and never roll back automatically. [Design 02 §§7–8](../system-design/rust-migration/02-target-architecture.md#L121), [Design 04 §§2, 7](../system-design/rust-migration/04-self-repair.md#L63), [ADR-0010 §§5, 7–8](../adr/0010-p6-trusted-build-activation-rollback.md#L76), [Current stage and switch](../../lifecycle-host/src/engine_switch.rs#L277), [Preflight validation](../../lifecycle-host/src/engine_switch.rs#L518), [Selector commit and fallback](../../lifecycle-host/src/engine_switch.rs#L824), [Current Store guard](../../lifecycle-host/src/store_guard.rs#L113)

## 15. Autonomous A → B → C

Install the root once through authenticated Owner enrollment. At each committed selector transition derive exactly one successor with the new accepted tree and package. Copy repository identity, published policy, Judge identities, resource scope, budgets and slot pool from the root. Preserve monotonic consumption and attempt budgets. Bind B's next authorization to B's committed generation and root, with a fresh incident, Repair, slot and operation. B receives predecessor status and history without authority to rewrite or reuse A's evidence. Host restart must recover the same chain from the exact selector commit. If the optional manual earlier selection is adopted, keep consumption monotonic and close protected admission whenever lineage or enrollment is ambiguous. [Design 04 §§8–10](../system-design/rust-migration/04-self-repair.md#L208), [Design 09 OD-2, OD-4](../system-design/rust-migration/09-open-decisions.md#L17), [ADR-0010 §9](../adr/0010-p6-trusted-build-activation-rollback.md#L145)

The `ClaimSlot` check currently asks only whether a slot is free. With the last free slot, the check succeeds even though the N+1 contract requires a usable slot for the successor. Verify a distinct, physically eligible successor slot before build/stage and enforce the reserved spare at claim, with permanent single-use claims and no silent recycling. Exhaustion holds at the current Engine before build or switch. Genuine A → B → C must exercise two trusted Parent authorizations with no recurring Owner approval and no push, then prove exhaustion and restart behavior. [Design 04 §§2, 8](../system-design/rust-migration/04-self-repair.md#L42), [Design 07 §6](../system-design/rust-migration/07-test-strategy.md#L74), [Current successor slot checks](../../runtime/core/p6Consumer.mjs#L443), [Root-bound Parent and slot pool amendment](2026-11-04-p6-genuine-contract-amendment.md#L46)

## 16. Cross-platform implications

Windows is the first target and each supported Windows release needs evidence. The design names Windows 10/11 while PR-1 proposes Windows 11. Linux needs its own proof of file and mount scope, open descriptor and IPC isolation, Host process and ptrace protection, no privilege gain, restricted network, and unescapable descendant termination and reconciliation. Namespace, Landlock, seccomp and cgroup features have platform and kernel prerequisites. A process group alone does not establish confinement of arbitrary descendants. macOS needs a supported and verified launch mechanism for each Engine, provider and build job and their descendants, with file, process, IPC, network and lifetime guarantees. Signed app sandbox entitlement configuration does not by itself establish per-Workflow enforcement for arbitrary tools. Keep protected Self-Repair unavailable on every OS/version without equivalent enforcement, including failed launch policy setup. [Design 03 §6](../system-design/rust-migration/03-trust-boundaries.md#L109), [Design 09 PR-1 and OD-3](../system-design/rust-migration/09-open-decisions.md#L5), [Linux Landlock](https://docs.kernel.org/userspace-api/landlock.html), [Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html), [Apple sandbox inheritance](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html)

## 17. Prioritized findings

### SR-01 · Critical · The Repair origin is unauthenticated

**Class and principal.** Proposed design contradiction. Repairable Engine. The Host allocates a slot after checking enrollment, capacity and concurrency. The required invariant is that a protected candidate originates from a Repair authorized by the enrolled Parent Judge. Fabricated labels satisfy the slot check. The candidate may pass the later independent Gate and Judge, producing a valid P5 acceptance for an unauthorized Repair. Spoofed labels also break Owner Stop lookup. Require the independently established, single-use P2 authorization and authoritative subject binding in §7. Prove denial for invented, substituted, stopped, stale and reused Parent/Repair/incident evidence, even when the candidate would pass P5. Owner decision is needed only to change the existing authorization contract. [Design 04 §§1–2.2](../system-design/rust-migration/04-self-repair.md#L26), [ADR-0012 §5.4](../adr/0012-rust-first-backend-and-engine-lifecycle.md#L59), [Current P2 capture](../../runtime/core/linkedRepair.mjs#L966), [Current Gate](../../runtime/core/p5Gate.mjs#L754)

### SR-02 · Critical · Workflow grants lack a trusted Run boundary

**Class and principal.** Proposed design contradiction under clarified OD-1. Engine, provider and descendants. The invariant is access only to the effective resource set authorized for the published Workflow and Run. The proposal uses per-SID ACLs but gives the long-lived Engine direct workspace grants and leaves effective Run publication and grant data in its Store. A hostile Engine can open another concurrent Workflow's root or claim its access through a launch. Put the Owner-authenticated resource manifest and Run/attempt tickets in Host state, with per-scope enforcement and alias checks from §10. Prove denial of cross-scope access, forged grants, aliases and unauthorized network endpoints alongside multi-root compatibility. A reduction in the promised scope or permission for uncontained managed providers needs an Owner decision. [Design 02 §7](../system-design/rust-migration/02-target-architecture.md#L121), [Design 03 §3](../system-design/rust-migration/03-trust-boundaries.md#L61), [Design 05 §§4, 6–7](../system-design/rust-migration/05-store-and-api.md#L87), [Design 09 OD-1](../system-design/rust-migration/09-open-decisions.md#L17), [Current launch inputs](../../lifecycle-host/src/custody.rs#L835)

### SR-03 · High · A captured Judge stream can carry a forged verdict or misleading consent

**Class and principal.** Missing design guarantee and trust decision. Judge/provider CLI, its descendants and Engine-mediated UI. Only the enrolled Judge decision on the exact protected dossier, with any authenticated and informed Owner answer, should count. Host custody and schema validation establish local invocation provenance. A compromised Judge executable, writable shared load/config state or uncontrolled descendant stdout can still emit a valid acceptance. A hostile Engine can misrepresent a protected question that the Owner answers. Apply §8, including isolated role/session, independently authenticated decision if CLI compromise remains in scope, and Host-owned consent presentation. Prove refusal of cross-job spool, tool/config substitution, stale decisions, replayed answers and relabeled questions. Owner decision is needed if the enrolled CLI itself is trusted to attest its own verdict. [Design 03 §§3, 5](../system-design/rust-migration/03-trust-boundaries.md#L61), [Design 04 §§4.2–4.4](../system-design/rust-migration/04-self-repair.md#L107), [Current question UI](../../src/App.tsx#L892)

### SR-04 · High · The proposed Gate reduces the causal predicate

**Class and principal.** Proposed contract regression. Candidate source, Verify job and Engine-selected reproducer. The Host protects named check files and records test listing, exit and output. It needs evidence that the required observable checks ran and that the same incident predicate actually failed on the enrolled baseline and passed on the candidate. A planted test can distinguish the tree and arrange a baseline-only failure. A linked candidate can exit early or spoof a listing. Require the same fixed, incident-bound inputs, a policy-protected expected failure and positive baseline control, and a trusted harness outside the candidate's process for security-relevant observations. Prove refusal for missing, skipped, spoofed, compile/load failure, crash, timeout and wrong-assertion results. Owner decision is needed for a weaker causal contract. [Design 04 §§3.2, 5](../system-design/rust-migration/04-self-repair.md#L79), [P5 causal verification amendment A2](2026-10-30-p5-closure-architecture-amendment.md#L50), [Current Gate settlement](../../runtime/core/p5Gate.mjs#L1140)

### SR-05 · High · Target process and channel isolation are unproven

**Class and principal.** Missing feasibility evidence. Engine, provider, verifier, builder and their descendants. The required invariant is that no confined subject reaches Host/Shell state, memory, handles, privileged IPC, or a more privileged launch path. The proposed AppContainer, Jobs and pipe allowlists have prototype support. A missed spawn, default or leftover listener, stale ACL or accessible broker could still provide a route. Treat possession of an Engine endpoint as Engine-domain authority, including calls relayed by the Engine. Restrict the semantic powers of that channel accordingly. Remove or reauthorize every legacy entry point, including standalone Custody, and apply fail-closed launch and role-specific dispatch. Prove PR-1, PR-2, PR-3 and PR-5 on the target launch paths. Owner decision is needed for any platform/provider exclusion or alternate trust model after a failed proof. [Design 03 §§1, 4–6](../system-design/rust-migration/03-trust-boundaries.md#L3), [Design 09 §1](../system-design/rust-migration/09-open-decisions.md#L5), [Standalone Custody entry](../../lifecycle-host/src/main.rs#L37), [Decision C §5](2026-11-06-p6-decision-c-design.md#L109)

### SR-06 · High · Package binding and the selector commit barrier are incomplete

**Class and principal.** Proposed design contradiction and missing guarantees. Malicious Engine, build job, or replayed operation. The Host receipt binds several digests and the existing switch verifies the package. The embedded build ID nevertheless depends on the final receipt that hashes the output, and the explicit validity check precedes preflight. A stale receipt or a Stop after preflight begins can reach commit if the Host lacks an exact, serialized binding. Adopt the acyclic ID, joined operation record and final commit guard in §14. Prove refusal of changed artifact, altered recipe, wrong acceptance, profile, generation, prior receipt and every pre-commit Stop interleaving. No Owner decision is needed. [Design 02 §6](../system-design/rust-migration/02-target-architecture.md#L109), [Design 04 §§6.1, 7](../system-design/rust-migration/04-self-repair.md#L145), [ADR-0010 §5](../adr/0010-p6-trusted-build-activation-rollback.md#L76), [Current commit](../../lifecycle-host/src/engine_switch.rs#L824)

### SR-07 · High · Git and Cargo identities do not yet seal the complete input and output

**Class and principal.** Missing design guarantees and feasibility evidence. Developer, candidate repository, Verify and Build jobs. The Host recomputes Git IDs and checks paths, while the toolchain and lockfile are pinned and jobs are intended to be offline. A valid unrelated commit can pass a tree diff. A nonstandard build-script input, ancestor Cargo config or mutable helper can change effective executable inputs. A build output can be redirected if collected by an unchecked pathname. Require exact enrolled predecessor and repository binding, strong canonical snapshot identity, sealed input/tool resolution and handle-safe collection after proven termination. Preserve the current managed candidate's required parent relationship. Expand PR-3, PR-4 and PR-6 to cover graph, path, configuration, tools and output substitution. Owner decision applies to OD-8 toolchain/target or reproducibility fallback. [Design 04 §§3, 5–7](../system-design/rust-migration/04-self-repair.md#L69), [Managed Git ancestry contract §25.5](2026-10-29-p5-managed-git-ancestry-and-host-boundary.md#L79), [Current Git candidate check](../../runtime/core/p5GitCandidate.mjs#L1304), [Existing source reconstruction](../../runtime/core/p6GitObjectSource.mjs#L60)

### SR-08 · High · Protected state can diverge across restart and exhaustion

**Class and principal.** Proposed contradiction and missing durable contract. Engine retry/replay and Host crash. Slots are intended to be permanent and the selector definitive. The claim predicate permits the last free slot, and the separate protected files lack a durable authority relationship. A crash can leave a selector without its successor or a claim without its charge. Specify the one authoritative protected transition and exact selector recovery in §12, and verify the N+1 invariant and successor slot in §15. Prove single consumption on duplicate delivery, no evidence reuse after abandonment, exact A → B → C across restart, and hold with no further build or staging on exhaustion or ambiguous records. No Owner decision is needed to preserve the current rule. [Design 04 §§2, 8–9](../system-design/rust-migration/04-self-repair.md#L42), [Design 05 §3](../system-design/rust-migration/05-store-and-api.md#L48), [Current successor checks](../../runtime/core/p6Consumer.mjs#L443)

### SR-09 · High · B's preflight grants conflict with the normal Engine profile

**Class and principal.** Proposed permission conflict. Candidate B and descendants. The Host guard stabilizes the Store and the proposal gives B only the copy, but the common Engine SID is listed on the real Store and B is meant to continue as the same process. If B has the ordinary SID/grants during preflight it can read real state, and stale or early grants can defeat the intended write boundary. Provide a separate effective identity for B's preflight, maintenance-only dispatch, and a post-commit production grant transition, with no access via stale handles, sidecars or aliases. Prove denial before commit, termination and unchanged original file identity on fallback, and continued normal execution after commit. No Owner decision is needed. [Design 02 §7](../system-design/rust-migration/02-target-architecture.md#L121), [Design 04 §7](../system-design/rust-migration/04-self-repair.md#L200), [Current Store guard](../../lifecycle-host/src/store_guard.rs#L113), [Current restart Store comparison](../../lifecycle-host/src/engine_switch.rs#L1156)

### SR-10 · High · Cutover retains a potentially exposed Owner bearer

**Class and principal.** Proposed cutover gap supported by a historical demonstration. Old Engine/provider code or a process with a retained credential. The proposal moves the token to a protected directory and preserves its value for clients. An attacker who retained a copy before cutover can still authenticate wherever it can reach the gateway. Rekey, retire old discovery copies and listeners, and prove rejection of the old credential with successful UI and external client rediscovery. Owner decision applies if preserving the old value despite potential prior disclosure. [Design 05 §§4, 7](../system-design/rust-migration/05-store-and-api.md#L96), [Design 06 §5](../system-design/rust-migration/06-migration-plan.md#L90), [Decision C §2](2026-11-06-p6-decision-c-design.md#L23)

### SR-H1 · Critical in the current Node architecture · Shared authority bypassed P5

**Class and principal.** Demonstrated historical defect. Engine and same-user child. Protected lifecycle commands and Owner/Store authority were reachable through the shared capability and user trust domain. The test-owned switch confirmed the consequence. Retain the release block on that topology. The proposed correction is Host-owned admission and switch, with positive refusal evidence for every child-reachable path under SR-05. Keep this evidence separate from future Rust feasibility. No new Owner decision is needed to preserve the release block. [Decision C §2](2026-11-06-p6-decision-c-design.md#L19), [ADR-0011 §§8–9](../adr/0011-engine-runtime-containment.md#L80), [Current Host dispatch](../../lifecycle-host/src/lib.rs#L1786), [Design 06 §4](../system-design/rust-migration/06-migration-plan.md#L81)

## 18. Required corrections

1. Establish protected P2 authorization before any protected slot claim. Keep the Parent Judge's authorization distinct from the Repair Judge's acceptance. Add a Host-owned subject, grant and invalidation record reusable by Custody and the final commit guard.
2. Make effective resource grants Host-enforced from authenticated Owner policy and immutable publication/Run binding. Scope tools, mutable session state, files, credentials, network and descendants per operation. Define an explicit decision trust boundary for enrolled Judge execution, including how protected Owner answers bind to what was shown.
3. Specify the sealed input and artifact chain and causal verification contract. Bind exactly one acceptance and current authorization to the receipt, prepared switch, selector and successor. Resolve the build-ID cycle, copy-only preflight, Stop ordering, claim and recovery rules.
4. Ship only on proven OS and provider combinations, using protected credential rebootstrap at cutover. Keep a failing provider or unsupported platform out of protected admission. A time window with uncontained managed providers under the same user cannot be used as a transparent fallback into later protected admission because those processes could already have modified Host state.

## 21. Final verdict

**`SECURITY REVIEW BLOCKED`**

Keep the two-backend-process topology. Require a single-use Host authorization for the exact Parent incident and Repair before any protected slot allocation, then carry it through P5 acceptance and the selector commit. That is the minimum correction for the unauthorized-update path. Close the Workflow grant and package/commit gaps and resolve trust in the enrolled Judge before treating containment experiments as release prerequisites for an otherwise coherent design.
