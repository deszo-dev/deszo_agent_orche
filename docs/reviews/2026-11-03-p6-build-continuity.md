## 4. Selected local source method and trust boundary

The selected method is Store-backed object reconstruction into the private managed clone. It does not add a Git server, durable cache database, or new source authority.

- [p6Reconstruction.mjs](../../runtime/core/p6Reconstruction.mjs) verifies the exact P5 handoff and Git-candidate references, rebuilds Git blobs/tree/commit bytes from immutable source artifacts, checks file modes and the accepted parent, and verifies the resulting object IDs.
- [p6GitObjectSource.mjs](../../runtime/core/p6GitObjectSource.mjs) validates the release-bound source descriptor against the P5 enrollment, baseline, Host-selected release, build receipt, continuation receipt, package identity and exact handoff. It rejects changed Store refs, wrong repository identity, wrong baseline, wrong parent and repeated operations.
- [p5GitCandidate.mjs](../../runtime/core/p5GitCandidate.mjs) materializes the verified P6 source chain into the private clone, fetches only the Owner-enrolled refs, and requires complete commit ancestry before accepting the baseline. The durable fetch marker binds the source descriptor so restart revalidates and rematerializes it.
- [p6Continuation.mjs](../../runtime/core/p6Continuation.mjs) carries the enrolled Git policy forward and adds a `verifiedLocalSource` descriptor only after the Host-committed release and continuation evidence match. Local object availability is not represented as remote publication; publication remains disabled unless the existing Owner policy authorizes a separate publication operation.

The packaged synthetic B run retained immutable P5 source records: handoff `edcb1127-cb71-4489-8057-3caa1386cafd` (SHA-256 `46f977db5f530bf789e74a6cf9dc07874b2ee210b5a5ea022ea7b86991069401`), source manifest `6b24333f-8bc2-47e9-80b9-ccb2b60a368b` (SHA-256 `7d9dcf4b21de48fb16447fda2ec8e24e14b3ddf865d1c90716f8f4f7697bc99a`, 185 entries), and Git candidate `5e9a3b54-38ed-4b7e-853b-5f58a0869071` (SHA-256 `259a86bbddd8ee38afbe78f2fc7511b9218aceb383e98fbf610063f77bfc4351`). These records came from the synthetic P6/G0 fixture, not genuine P5 acceptance.

The positive object-materialization unit case verifies exact blobs, executable mode, tree and commit IDs; rejects changed blob, mode, tree or commit; proves a partial materialization can be completed; and proves a missing local object database can be reconstructed after restart. It also shows that exact local B plus advertised enrolled A gives complete ancestry without writing a branch or publishing B.

**F-15 disposition:** root cause reproduced and a narrow source implementation is present. The integrated positive path is **not yet verified**: no test passes a valid `verifiedLocalSource` descriptor through `verifyP6GitObjectSource` and `prepareP5WorkspaceFromIntent` to produce a fresh managed clone from B. The exact F-15 negative case and the materializer unit case are complementary, not an end-to-end proof.

## 5. Pre-switch continuity and continuation

[p6Consumer.mjs](../../runtime/core/p6Consumer.mjs) now treats successor source continuity as a pre-switch invariant. It reconstructs the accepted Git provenance, verifies the enrolled Git tool and predecessor baseline, materializes into an isolated object probe, fetches only enrolled refs, and checks complete ancestry before requesting Host stage/switch. A failure is durably refused before the Host switch boundary.

The successor descriptor binds the accepted handoff, candidate source digest, Git commit/tree/object format, Host installation and Engine build, P6 operation, package digest, build receipt and continuation receipt. Parent P6 sources are verified and materialized recursively, so a later successor does not depend on publishing an earlier P6 commit.

Continuation replay permits an immutable Host phase advance from `committed` to `verified`, while rejecting regression and changes to operation, package or release identity. A concurrent first-writer comparison now returns the already persisted immutable receipt when its identity matches. Its comparator test covers the allowed advance, timestamp variation, regression and identity changes; there is not yet a test with two concurrent continuation resolver calls.
