# ADR-0006 route and credential matrix

The runtime is in candidate mode whenever it has an authenticated host binding. `manual` in a request is not a mode switch. In production that mode's startup descriptor contains only an external credential. Tauri forwards the same restricted descriptor; it receives no first-party credential. Non-packaged fixture tests retain a first-party test credential to verify that engine guards also refuse legacy authority. These constraints supplement [ADR-0001](0001-external-workflow-authoring-api-and-mcp.md) and the [autonomy decision](0006-time-bounded-autonomy-and-application-lifecycle.md).

| Route or operation family | Manual runtime | Host-bound candidate | Enforcement |
| --- | --- | --- | --- |
| Read contracts, workflows, runs, events, artifacts, evidence, receipts | Existing credential | External credential | HTTP authentication and existing result bounds |
| Workflow validation, bridge handshake | Existing credential | External credential, no dispatch | Existing schemas |
| Save workflow revisions | Existing credential | Refused | Engine `refuseHostMutation`; a revision must be prepared outside the candidate and explicitly included in consent |
| Settings, workspace registration, cache pins | First-party | Refused | Engine `refuseHostMutation` before mutation |
| Context acknowledge and messages | First-party | Refused | Engine guard; no correlation/compatibility override or uncharged chat |
| Create run (HTTP, MCP, Tauri, direct engine) | Existing confirmation policy | Exact host permit, generation, workspace and snapshot plus engine checks | `createRunUnderHostPermit`; unpermitted run guard |
| Pending run decision | First-party | Cannot dispatch without exact host admission | Run-creation guard; use a new host-permitted request |
| Controller session and request supervision | Existing credential | External credential; still pending | Existing controller/session contracts |
| Approve supervision | First-party | Exact `supervision.approve` permit; no ordinary approval shortcut | Host approval endpoint and engine-owned admission object |
| Revoke supervision, stop run/node | Existing authority | Existing authority; does not start work | Existing engine validation |
| Recovery | First-party | Only close; retry/resume requires a new exact run | Engine guard before recovery mutation |
| Extend supervision deadline | First-party | Refused | Engine guard; original bounds cannot expand |
| Observe, processed event ACK, Stop-and-report, incident and audit evidence | Existing controller/external authority | Same existing scoped authority | ADR-0002 session, cursor and evidence validation; host approval cannot forge an ACK |
| Incident triage/closure | First-party | Refused | Engine guard; reporting remains available |
| Provider invocation, including context continuation/retry | Engine dispatch | Separate host reservation/admission/settlement per invocation | `reserveHostProviderInvocation` at CLI boundary |
| Managed-task repair cycle | Engine task bounds | Exact `repair.run` permit derived from persisted task/cycle before its first provider invocation | Several roles/context turns share one durable cycle receipt. Context-only expansion with zero repairs consumes no repair; provider calls retain separate charges. |
| Policy create/extend/widen/post-reboot | No ordinary runtime authority | Proposal only | Installed broker + fresh Windows Hello signature over exact service decision |
| Host register/restart/rollback/check/build | No legacy token authority | Scoped native IPC and exact host permit only | Protected service, independently observed process and native Job |
| Planned application close (`lifecycle.stop`) | No legacy token authority | Authenticated controller, explicit `app.stop`, exact runtime generation and verified host launch; idle owned work and no other pending queue items | Request contract excludes supplied PIDs, commands and success claims. The fixed worker may execute its own authenticated, leased `lifecycle.stop` step for one exact ready build/generation. Durable Stop fences new decisions/admissions/queue claims, invalidates outstanding permits and retires the old generation before the native call. Native domain-empty plus application/Node exit proof is required. One operation, zero restarts; original policy/expiry retained. Installed normal Stop is observed; the complete replacement/foreground sequence remains under native verification. |
| Emergency Stop/revoke | Authenticated native user or existing controller scope | Existing safety path, including exhausted/blocked dispatch | Does not depend on the new planned-close API. Revocation cannot authorize another launch. |
| Verification-only diagnostic policy | Fresh decision-bound Windows Hello | Only explicitly listed `app.verify`, `app.stop`, `runtime.reregister`, `run.stop_and_report`; zero provider/workflow/model/build/repair authority | `app.stop` additionally requires its own verified diagnostic generation. It is not inferred from `app.verify`: the superseded diagnostic policy lacked this permission; the physically authorized revision 2 includes it. No production capabilities are promoted. Source/compilation and stable-controller gaps remain. |
| Native activation during required UI verification | No general computer-control route | Private service-to-launcher action for the exact owned application, user, session and generation | One bounded Win32 foreground request, no synthetic input/security-dialog control. Denied activation or an unavailable/changed desktop blocks UI acceptance. Activation and capture observations must match birth/session/generation before a PNG is persisted. Installed; the complete source-bound cooperative replacement sequence remains under native verification. |
| Cooperative foreground handoff (`application.launcher_identity`) | Not used | Native helper's actual parent must be a host-launched application in its exact owned domain and decided desktop | Identifiers alone grant nothing. The service returns its verified launcher identity; Tauri pins the actual process handle and checks birth before AllowSetForegroundWindow, excluding ASFW_ANY. This is Windows activation eligibility, not Deszo approval or a credential. |
| Broker foreground return (`consent.launcher_identity`) | Protected broker only | Protected broker OS role and an already active, authorized matching desktop session | No policy creation/extension or synthetic verification. Broker may return foreground eligibility on close, and closes automatically only after real WebAuthn plus the matching committed active-policy receipt. The new auto-close path still requires physical-consent acceptance evidence. |
| Desktop input/foreground timing inspection | Elevated installation operator | Read-only native launcher observation | Reports input idle time, foreground lock timeout and observation gaps. Does not read screen content, change Windows settings or prove that activation will be allowed. |
| Node runtime.reregister | No legacy token authority | Installed native peer, verified original application parent/build/profile, terminated predecessor and no unresolved work; explicit runtime.reregister policy scope | A fresh generation consumes one shared restart/operation, preserves original expiry and retires the previous generation. No consumed nonce is reused. |
| Queue/operation reconciliation | Existing authorized controller/installation operator | Fixed native Stop and actual process/admission observations; caller success/evidence fields are refused | Unknown steps become interrupted/stopped without advancement or replay; full unknown charges remain counted. |
| Deferred incident delivery | Existing external reporting | Host outbox request/body, original registered profile/store, engine durable request receipt | Native Stop precedes reporting; unavailable transport retains the incident; no run or lifecycle effect is retried. |

Host absence, invalid registration, a failed permit or an unavailable launcher cannot fall back to the manual path. Supported candidate content is additionally constrained by the approved build closure: replacing authorization code cannot become authorized by changing a request label. This boundary does not sandbox arbitrary same-user code outside host-mediated operations.

The five `adr6-application-stop.test.mjs` scenarios cover the planned-close domain contract with injected native observations: rights/target refusal, replacement-safe receipt replay, idle-work checks, concurrent admission/queue fencing, timeout/lost reply and incomplete termination. `adr6-verification-bootstrap.test.mjs` additionally covers explicit diagnostic scope and the exact leased Stop step. `adr6-native-ui.test.mjs` covers bound capture, activation refusal, wrong identity/image and unavailable desktop with injected native observations. Rust reply-validation tests reject unverified/substituted helper replies and unsafe target PIDs. These do not establish complete HTTP/Tauri or installed native acceptance. Continuation 7 adds real HTTP negatives in `adr6-route-matrix.test.mjs`: settings, workspace registration, workflow revision, context acknowledgement and messages, supervision deadline extension and approval, incident triage, cache pins and recovery retry are each refused in a host-bound candidate. The first-party credential reaches the engine, which refuses with `trusted_authority_required`; the external credential is refused earlier by the HTTP role gate (`forbidden`). Tauri command-path and MCP negatives remain open. The updated service has an actual verified planned Stop, with the cooperative replacement/foreground sequence still under verification; source-bound production receipts remain absent.

The activation path respects [Windows foreground restrictions](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow). A successful request alone is not proof of focus; the native launcher observes the actual foreground window. This cannot guarantee unattended focus while another application is receiving user input.

The closing foreground application/broker uses [AllowSetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow) for one verified launcher process. Subsequent user input can revoke that Windows eligibility. Consent validity and Windows foreground eligibility remain separate boundaries.

Continuation 8 adds two route facts. `adr6-bridge-credentials.test.mjs` runs real stdio bridges: a bridge that did not create a controller session is refused for `start_run` with `controller_credential_required` before any request reaches the runtime, and no run is created. The installed service gains `incidents.spool`, which is available only to the authorized desktop user (the installation user, with a session). It files an observation under a policy through the outbox; filing starts no runtime and grants no authority. The route exists in source and in `.deszo/build` until the protected update installs it, and no fixture tests the service-side gate, because that code runs only inside the installed service.
