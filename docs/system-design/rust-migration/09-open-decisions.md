# 09. Open decisions and prerequisites

Revised 2026-11-06 after the independent reviews. Only items that materially change implementation are listed. Each prerequisite is a bounded feasibility experiment scheduled in M1 ([06 §2](06-migration-plan.md#2-stages-and-dependencies)); none was executed in this design work. A failed prerequisite never becomes an accepted limitation: it amends the design or triggers the Owner decision named in its row.

## 1. Prerequisites

| ID | Experiment | Pass criteria | Fail consequence | Blocks |
|---|---|---|---|---|
| PR-1 | Engine and OS boundary on each supported Windows release, without administrator rights: a skeleton Rust Engine under its per-build principal with SQLite WAL in its Store, typed pipes, kill-on-close | Runs; denied: Host and Shell process open, memory read and handle duplication; Host, gateway and enrollment directories, old and new token and descriptor paths; ungranted folders; loopback and any network access (the Engine principal has no network capability); breakaway from the Job. Children and grandchildren inherit the token; a contained process cannot open another contained process; behavior holds across Engine restart. **G0 grant transition:** a maintenance-mode B is denied the live Store before commit, and after the access-control transition on a Store of realistic size (at least the largest profile in M0) B opens it; the transition time is measured | Revisit the control in 03; for the grant transition, OD-9 | M4, M5, M8 |
