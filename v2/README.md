# Deszo v2 — новая версия Agent Orchestrator

> **Статус: начало разработки / изолированная рабочая область.**  
> Эта папка — место, где с нуля строится следующая версия Deszo. Наличие `v2/` не означает, что новая версия уже готова или заменила текущую.

## Назначение

В `v2/` ведётся проектирование и разработка новой архитектуры Deszo. Это самостоятельная рабочая область внутри существующего репозитория: новые компоненты, конфигурации, тесты и документация v2 размещаются здесь, чтобы не смешивать их с текущей реализацией в корне.

В качестве направления рассматривается **container-native Agent Orchestrator**: Rust control plane, управление локальными и в перспективе удалёнными Execution Nodes, Docker Runtime Pools для Codex/Claude/AGY, отдельные сущности Agent / Session / CLI Invocation / Container и независимые от контейнеров Workspaces. Это **архитектурное направление для проработки**, а не набор уже реализованных или окончательно принятых решений.

Обзорная диаграмма новой концепции находится в соседнем репозитории System Design:

- [deszo_agent_orche_SD / container_native_architecture.excalidraw](https://github.com/deszo-dev/deszo_apps_system_design/blob/main/deszo_agent_orche_SD/container_native_architecture.excalidraw)
- [deszo_agent_orche_SD / README.md](https://github.com/deszo-dev/deszo_apps_system_design/blob/main/deszo_agent_orche_SD/README.md)

## Правила переходного периода

1. **Всё новое для v2 создаётся внутри `v2/`.** Не добавлять новую реализацию v2 в существующие корневые `runtime/`, `src/`, `src-tauri/`, `lifecycle-host/` и другие legacy-каталоги без отдельного обоснованного решения.
2. **Всё за пределами `v2/` считается текущей / legacy-частью репозитория** до проведения инвентаризации и миграции. Не считать её частью v2 автоматически.
3. **Каждый существующий компонент рассматривается отдельно:** он либо переносится (при необходимости перерабатывается) в `v2/`, либо признаётся ненужным и впоследствии удаляется. Перенос не подразумевает копирование старой архитектуры без пересмотра.
4. **Ничего снаружи `v2/` не удалять автоматически.** Перед удалением или перемещением проверить зависимости, необходимые данные, тесты, документацию и возможность восстановления; выполнять изменения осознанно, отдельными проверяемыми шагами.
5. **Не ломать действующую реализацию ради v2.** Во время разработки обе области могут временно сосуществовать в одном репозитории. Любые общие зависимости должны быть явными и временными.
6. **До готовности v2 корень репозитория остаётся текущим workspace.** Разработка в `v2/` сама по себе не переводит проект на новую версию.

## Конечная цель

Когда v2 будет завершена, проверена и явно принята для замены текущей реализации:

1. Зафиксировать состав новой версии и подтверждённый план миграции.
2. Перенести в `v2/` необходимые остающиеся компоненты и данные; исключить ненужное legacy.
3. Подтвердить сборку, тесты, запуск, восстановление данных и основные сценарии работы новой версии.
4. **Переместить содержимое `v2/` в корень репозитория** — новый основной workspace Deszo. Не сохранять `v2/` как постоянную обязательную вложенную директорию приложения.
5. Удалить устаревшие корневые файлы только после подтверждения их замены, при необходимости поправить пути, CI/CD, документацию, сборку и инструкции запуска.
6. Сохранить историю изменений в Git и оформить переход отдельным проверяемым изменением.

После этого **новая версия Deszo живёт непосредственно в корне `deszo_agent_orche`**, а временная директория `v2/` больше не нужна.

## Важно

Этот README фиксирует стратегию организации разработки и будущего перехода. Он не разрешает массовое удаление существующего кода, изменение production, автоматический перенос файлов или замену утверждённых архитектурных решений. Конкретные ADR, контракты, зависимости и критерии готовности v2 оформляются в процессе проектирования.
